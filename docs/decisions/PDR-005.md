# PDR-005: Govern and strictly evaluate private real-note data

**Date**: 2026-08-01
**Status**: Accepted

## Decision proposed

Adopt the following package before collecting real notes:

- `datasets/REAL_DATA_GOVERNANCE.md`
- `datasets/REAL_DATA_ANNOTATION_GUIDE.md`
- `datasets/REAL_DATA_SPLIT_AND_SEALING_PROTOCOL.md`
- `training/REAL_DATA_EVALUATION_PROTOCOL.md`

The package makes real-note collection and evaluation conditional on explicit consent, de-identification, private provenance, fixed split roles, structured logging, and strict human semantic scoring.

## Proposed gates

1. Retain Phase D's empty validation/holdout separation.
2. Add explicit ignore rules for `datasets/private/`, `training/results/private/`, real source files, processed validation, and the legacy processed-holdout path before creating private artifacts.
3. Remove routine holdout loading and materialization from `prepare_data.py`.
4. Make `evaluate_holdout.py` load and validate the sealed source directly in memory only at a declared release milestone.
5. Synchronize the source-determined bullet contract in `training/prepare_data.py` and the thought-organizer-app's `src/services/noteOrganizer.ts`; verify matching contract versions and rendered-prompt hashes.
6. Implement private record manifests and rubric sidecars at the paths defined by the package.
7. Implement deterministic record, dataset, rubric, checkpoint, and prompt-contract fingerprints.
8. Implement structured private evaluation logs.
9. Implement the strict semantic-scoring scaffold.
10. Verify the full workflow with synthetic dummy records, including ignore checks and withdrawal.
11. Complete a second joint readiness review.
12. Run a validation-only pilot of at most eight records.
13. Keep the sealed holdout empty until the pilot process is reviewed and separately approved.

## Reasoning

Phase D successfully separates routine validation from explicit holdout evaluation, but empty-file separation alone does not make real-data use safe or decision-ready.

Without governance, the project cannot establish consent, authorship, provenance, de-identification, withdrawal, or private handling. Without structured logs, results are not reproducible. Without semantic scoring, format validity repeats the same proxy-metric failure pattern previously observed with evaluation loss. Without removing routine holdout materialization, the supposedly sealed content is opened and duplicated during ordinary preparation.

The proposed package addresses these failures before collection rather than after private data exists.

## Prompt-contract clarification

The package proposes source-determined bullet counts. A one-idea note receives one bullet and is never padded to meet a nominal minimum. The current 3–7 instruction exists in both the training prompt and the production app prompt. Because those templates are intended to match exactly, this is a paired cross-repository dependency. Neither repository may change alone, and the pilot remains blocked until both prompt builders report the same contract version and produce byte-identical rendered prompts for the acceptance fixture.

The thought-organizer-app repository is maintained in a separate chat scope. PDR-005 tracks the dependency but does not authorize editing that repository from this project scope.

## Schema clarification

The annotation guide uses the repository's full four-tier difficulty enum: `easy`, `medium`, `hard`, and `expert`.

## Private paths and fingerprint decisions

Revision 2 fixes concrete locations for private manifests, rubrics, and evaluation logs and defines deterministic SHA-256 algorithms for records, datasets, checkpoints, rubrics, and prompt contracts. These are implementation requirements rather than deferred design choices.

## Scope boundaries

- No diagnosis or contributor classification.
- No outside-contributor recruitment during the pilot.
- No holdout population during the pilot.
- No real-data training or publication.
- No automated semantic scorer is approved by this decision.
- No Gold v1.3 Sensory Overwhelm work is included.
