# PDR-007: License the whole project CC BY-NC-SA 4.0 (code, docs, model weights)

**Date**: 2026-08-12
**Status**: Accepted

## Decision

The project as a whole — training/inference code, documentation, and
released model weights (`intent-recovery-model-*` releases) — is licensed
**CC BY-NC-SA 4.0** (Attribution-NonCommercial-ShareAlike), via a new
project-wide root [`LICENSE`](../../LICENSE) file. This extends
[PDR-006](PDR-006.md)'s dataset-only decision to the rest of the project,
closing the gap PDR-006 explicitly left open ("the code, documentation,
and model-weight licenses are separately gated... and are not decided by
this record").

## Reasoning

PDR-006 settled the project's overall policy — permanently noncommercial
(prospectively), attribution-required, ShareAlike propagated to forks —
but scoped its actual license change to `datasets/gold/` only.

Asked directly whether it matters that forks of the *code* specifically
stay noncommercial too (ShareAlike), versus merely stopping direct
commercial use of distributed copies: the product owner's answer was that
ShareAlike matters, for one consistent license family across the whole
project rather than tracking multiple regimes.

### Why not a software-specific license

Creative Commons licenses are not designed for software — confirmed
directly against Creative Commons' own guidance: no source-code-specific
terms, no patent-grant framework, and incompatibility with the GPL (over
half of free software uses GPL-family licenses). The purpose-built
alternative for "noncommercial software" is **PolyForm Noncommercial
1.0.0**, a real, actively-used license with an actual patent grant — but
it has no ShareAlike/copyleft mechanism: it stops a licensee from
commercial use of what they receive, but does not require a fork's own
modifications to carry the same restriction forward. Given the product
owner's explicit preference for ShareAlike propagation, PolyForm
Noncommercial was not selected. CC BY-NC-SA 4.0 is used for code anyway,
trading the software-specific precision Creative Commons itself
recommends against for consistency with the rest of the project and the
ShareAlike guarantee.

### Model weights

`google/flan-t5-base` (the base model) is Apache 2.0 — permissive, not
copyleft. Apache 2.0 §4 explicitly permits a licensee to "provide
additional or different license terms... for any such Derivative Works,"
so fine-tuning it does not constrain what license the resulting weights
can carry. CC BY-NC-SA 4.0 applies to the fine-tuned weights; Google's
original Apache 2.0 notice for the base model remains intact and is not
superseded.

No prior grant exists for the weights to account for. Unlike
`datasets/gold/`'s CC-BY-4.0 history, the existing
`intent-recovery-model-v0.1.0` release (published 2026-07-29, checked
directly before drafting this PDR) carries no license statement at all —
meaning default "all rights reserved" copyright applied until now. Adding
a CC BY-NC-SA 4.0 statement to it is a strict expansion of rights for
anyone who already holds a copy, not a restriction, so there is no
historical-exception carve-out analogous to PDR-006's needed here.

## Scope

- Project-wide root [`LICENSE`](../../LICENSE) — new file, covers
  everything not otherwise specified (code, documentation).
- `datasets/gold/` keeps its own
  [`LICENSE.md`](../../datasets/gold/LICENSE.md) (CC BY-NC-SA 4.0 from
  2026-08-12 forward, CC-BY-4.0 historical exception for `gold_v1.0`
  through `gold_v1.2.3` — see PDR-006). Not changed by this PDR beyond a
  cross-reference to the new root file.
- `datasets/real_validation.jsonl` / `datasets/real_holdout.jsonl` remain
  unlicensed, excluded from version control, never published (PDR-004).
- The existing `intent-recovery-model-v0.1.0` GitHub Release notes
  updated to state the license, since it previously had none.

## GitHub-specific note

Same caveat as PDR-006: GitHub's license detector doesn't reliably
recognize CC-BY-NC-SA-4.0 even from a root-level file
(`licensee/licensee#343`, independently confirmed during PDR-006). Adding
the root `LICENSE` file is still best practice — the repo sidebar badge
may continue to read "no license" or show nothing; this doesn't affect
legal validity.
