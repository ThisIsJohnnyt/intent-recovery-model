# PDR-003: Split into intent-recovery-model and thought-organizer repos

**Date**: 2026-07-29
**Status**: Accepted

## Decision

Split this repository into two independent GitHub repositories:

- **`intent-recovery-model`** — the fine-tuning pipeline, datasets,
  evaluation/benchmark suite, and the AI-collaboration documentation layer
  (`training/`, `datasets/`, `docs/`, `research/`). Created by renaming this
  repository, preserving its full history.
- **`thought-organizer`** — the React/Vite note-organizing application
  (`src/`, `public/`, config). Created fresh, copying the app-relevant
  paths, with a smaller history than the model repo since most of this
  project's iteration so far has been on the dataset/training/process side.

The two are connected by a versioned **Intent Recovery Inference Contract**
(see `docs/inference-contract.md`) rather than the app depending on the
model repo's internal training format directly, and the app consumes the
model as a downloaded, checksummed release artifact rather than a
committed binary.

"Intent Recovery" (already this project's name for its core task, per
`docs/vision/NORTH_STAR.md`) is adopted as the umbrella name for the
model/methodology side. The short form "IRM" is explicitly rejected — it
collides with "Invariant Risk Minimization," an established ML term.

## Reasoning

The dataset/training/process side of this project has grown into something
with independent value: a documented methodology for multi-AI-collaborative
dataset curation (`docs/vision/AI_COLLABORATION.md`), a versioned dataset
release process (`docs/datasets/REVIEW_GUIDE.md`), and a working fine-tuning
pipeline — none of which requires the specific note-organizing application
to be useful to someone else. Keeping them in one repository forces anyone
who wants just the model/methodology to also take the app, and vice versa.

Git history composition supports renaming the current repository rather
than splitting it with `git filter-repo`: of 20 commits at the time of this
decision, roughly 17 are dataset/training/docs/process-focused; only the
earliest few touch application work, and even those are mixed rather than
pure-app. Renaming preserves 100% of the history that actually matters to
future maintainers of the model/methodology side; the app repository
starting fresh loses only a handful of early, largely superseded commits.

The inference contract and checksummed release artifact (rather than a
submodule or a directly committed binary) keep the two repositories
genuinely independent — the model can change its internal format, training
schema, or export process without forcing an application change, as long as
the contract's major version holds. This also preserves the project's
existing on-device, no-server-data privacy principle
(`docs/vision/NORTH_STAR.md`): the application still runs entirely locally
against a downloaded artifact, never a hosted inference service.

## Approach

See [`PDR-003-migration-plan.md`](PDR-003-migration-plan.md) for the full
step-by-step sequence. Summary: tag the pre-split state, define the
inference contract and a migration manifest before moving anything, cut the
first checksummed model release, prove the new application repository
works end-to-end from a fresh clone, *then* rename the original repository
and remove the now-migrated application files from it — never removing
anything until its replacement is proven working.
