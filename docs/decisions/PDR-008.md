# PDR-008: Correct PDR-007 — three artifact-appropriate license classes, not one

**Date**: 2026-08-12
**Status**: Accepted
**Supersedes**: [PDR-007](PDR-007.md) in part (its software and model-weight
decisions; its dataset/documentation scope is unaffected and PDR-006 stands
unchanged)

## Decision

Replace PDR-007's single project-wide CC BY-NC-SA 4.0 license with three
artifact-appropriate classes:

1. **Dataset and documentation**: CC BY-NC-SA 4.0 — unchanged from PDR-007.
   Human-authored prose, clearly copyrightable, no ownership doubt.
2. **Software** (`training/*.py` and other code): **PolyForm Noncommercial
   1.0.0**, not CC BY-NC-SA 4.0. A real software license — copyright grant,
   distribution/modification terms, an actual patent grant — at the cost of
   not legally forcing a fork's own new modifications to stay noncommercial.
3. **Released model weights**: no asserted copyright license. A plain
   request (acknowledgment + noncommercial use), explicitly not represented
   as a legally enforceable condition, given genuinely unsettled
   copyrightability. See [`MODEL_RELEASE_NOTICE.md`](../../MODEL_RELEASE_NOTICE.md).

The root [`LICENSE`](../../LICENSE) file is rewritten to route to these
three classes plus the dataset's historical exception and the excluded
private data, rather than claiming one blanket license covers the whole
repository.

## Reasoning

### Why PDR-007 was wrong, not just imprecise

PDR-007 kept code under CC BY-NC-SA 4.0, treating the license's missing
patent grant and lack of a source-code-delivery clause as disclosed,
acceptable limitations. Independent review (ChatGPT) and Claude's own
verification against the actual legal code found this doesn't meet the
product owner's stated goal:

- CC's ShareAlike condition (legal code §3(b)) applies when someone
  "Shares Adapted Material," and CC's "Share" definition has no
  preferred-source/source-code-delivery requirement the way GPL-family
  copyleft licenses do. A modified version could technically comply with
  CC BY-NC-SA's letter while distributing only compiled/object output —
  undermining the actual "forks stay forkable" goal, not just missing a
  nice-to-have.
- CC BY-NC-SA 4.0 explicitly excludes patents: §2(b)(2), "Patent and
  trademark rights are not licensed under this Public License" — confirmed
  directly against the legal code.
- Creative Commons' own guidance recommends against CC licenses for
  software specifically because of gaps like these.

PDR-007 also stated model weights "carry this same license" without
qualifying that CC licenses only operate where copyright/similar rights
exist and are owned by the licensor — a materially incomplete claim given
unsettled weight-copyrightability law (see below).

### Software: PolyForm Noncommercial over custom terms

Presented directly to the product owner: is enforceable identical licensing
of a fork's own new code (full ShareAlike-equivalent propagation) important
enough to justify pursuing custom, professionally-reviewed license terms —
or is PolyForm Noncommercial's honest, software-appropriate approach
(real patent grant, stops commercial use of the distributed code, but a
fork's brand-new additions aren't legally forced to stay noncommercial)
good enough? Product owner chose PolyForm Noncommercial, consistent with a
stated preference for clean, honest terms over maximal enforcement, and
given the modest actual goal (acknowledgment, not aggressive restriction).

### Model weights: request, not restriction

The product owner clarified the actual goal directly: acknowledgment as the
project's originator, not ownership or copyright claims over the weights,
the model, or "anything" beyond what's clearly his. This matters because it
changes what needs to be legally defensible. An enforceable *restriction*
on weight use needs a real copyright (or other) hook; a plain
acknowledgment *request* doesn't — it can be stated honestly regardless of
whether that hook exists.

The underlying uncertainty is real, not overcautious: the U.S. Copyright
Office's Part III report (May 2025) on AI and copyright discusses model
weights that substantially memorize training data potentially constituting
infringing copies of the *original* copyrighted material — a risk layer
independent of whether the weights are copyrightable in their own right.
Read directly, not taken from the review secondhand, before accepting this
as a basis for the decision. No blanket rule resolves either question
today. Given that, and given the product owner's own preference to "not
put any restrictions on it that are not legally clear," `MODEL_RELEASE_NOTICE.md`
states the acknowledgment/noncommercial-use ask as a request, explicitly
not a license condition, and discloses (without alleging) the memorization/
third-party-rights uncertainty plainly.

### FLAN-T5 was never in question — this closes a compliance gap, not a licensing-clarity gap

The product owner's assumption that `google/flan-t5-base` is genuinely open
was correct — verified repeatedly this session, Apache 2.0, confirmed
directly on Google's own model card. The actual gap was narrower: Apache
2.0 §4 has real redistribution conditions (license copy, modification
notices, retained copyright/patent/trademark notices, NOTICE-file
reproduction) that the `v0.1.0` release never satisfied — not because
FLAN-T5's terms were unclear, but because those conditions were never
implemented. See [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md)
for the completed provenance inventory and compliance record, verified
directly against `training/export_onnx.py` and the actual `v0.1.0` release
assets rather than assumed.

One honestly-disclosed limitation surfaced while completing that inventory:
`training/train.py` never pinned an explicit Hugging Face revision for
`google/flan-t5-base` (confirmed by reading the script), so `v0.1.0`'s
exact base-model bytes aren't forensically reproducible after the fact —
unlike later experiments, which do pin a specific revision. `train.py` is
updated in this change to pin that revision explicitly going forward;
`v0.1.0`'s gap is disclosed, not retroactively fabricated.

### Root LICENSE correction

PDR-007's root `LICENSE` said "This repository... is licensed" — a blanket
claim that could be read as asserting ownership over vendored/third-party/
dependency content it doesn't actually own. Corrected to state explicitly
that only copyright and similar rights actually owned or licensable by the
product owner are being licensed, routed per artifact class.

## Scope

- `datasets/gold/` — unchanged, still governed entirely by
  [PDR-006](PDR-006.md) (CC BY-NC-SA 4.0 + CC-BY-4.0 historical exception).
- Documentation (`docs/`, `README.md`, dataset cards, decision records) —
  CC BY-NC-SA 4.0, unchanged from PDR-007.
- Software (`training/*.py`) — **changed**: PolyForm Noncommercial 1.0.0,
  not CC BY-NC-SA 4.0.
- Released model weights — **changed**: request-based
  (`MODEL_RELEASE_NOTICE.md`), not an asserted CC BY-NC-SA 4.0 license.
- `training/train.py` — pins `google/flan-t5-base` to an explicit revision
  going forward.
- `intent-recovery-model-v0.1.0` GitHub Release — notes and attached assets
  updated to reflect this PDR, `THIRD_PARTY_NOTICES.md`, and
  `MODEL_RELEASE_NOTICE.md`.
- Private data (`datasets/real_validation.jsonl`, `datasets/real_holdout.jsonl`)
  — unchanged, unlicensed, excluded, never published (PDR-004).

## What this PDR does not do

Does not obtain formal legal counsel — the product owner explicitly weighed
that against PolyForm Noncommercial's more modest, honestly-scoped
guarantee and chose the latter, given the project's actual goals. Does not
perform a memorization/output-provenance audit of any released checkpoint
— disclosed as an open gap in `MODEL_RELEASE_NOTICE.md`, not resolved here.
Does not establish trademark or brand protection for the project name —
noted as a separate, not-yet-needed question if it ever matters.
